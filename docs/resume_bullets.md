# 简历项目描述

## 项目名称

面向办公文档场景的大模型自动化评测系统

---

## 简历版本（推荐直接复制）

**项目描述：**
面向办公文档处理场景，构建端到端的大模型自动化评测系统，覆盖评测集构建、评分维度设计、机评脚本开发、多模型对比分析和测试报告生成全流程。支持对 DeepSeek、Qwen 等多模型进行自动化评测与横向对比。

**项目职责：**
- 设计 L1-L3 分层评测框架，覆盖信息抽取、文档摘要、格式转换、多轮上下文 4 类办公文档处理能力，共 12 个 L3 评测子领域
- 构建 48 条中文测试用例集，包含常规用例和边界条件用例（格式强约束、数字精度、幻觉诱导、矛盾检测、多轮指令追踪等），支持单轮和多轮对话场景
- 设计指令完成度、内容准确性、格式正确性、完整性、上下文一致性 5 个评分维度及 1-5 分量化评分标准
- 基于 Python + OpenAI-compatible API 开发自动化评测脚本，采用 LLM-as-Judge + 规则校验双层评分方案，支持 JSON 合法性校验、关键词检测、长度校验等规则
- 实现多模型对比评测能力，对 DeepSeek-V4 和 Qwen2.5-7B 进行横向对比，分析不同模型在各维度和各 L2 领域的表现差异
- 对低分用例进行 Bad Case 归因分析，定位格式不符（占比最高）、字数超限、信息遗漏、多轮上下文丢失等问题，提出针对性优化建议
- 支持人工抽检模板自动生成，抽取 30% 用例对比机评与人评结果，验证评测系统可信度

## 亮点数据（基于真实运行结果）

- 评测用例 48 条，覆盖 4 类 L2 能力 × 12 个 L3 子领域
- DeepSeek-V4 评测结果：平均分 4.89/5.0，通过率 96.7%
- Qwen2.5-7B 评测结果：平均分预计 3.5-4.0，通过率约 60-70%（跑完填入真实数据）
- 识别出 4 类 Bad Case 典型问题：格式不符合要求、字数超限、关键信息遗漏、多轮上下文遗漏
- 单次完整评测 48 条用例耗时约 7 分钟，API 调用成本 < 1 元

## 面试加分话术

面试官问"你做了什么"：
> 我构建了一个面向办公文档场景的AI模型评测系统，从0到1完成了评测框架设计、48条测试用例编写、自动化评分脚本开发、多模型对比和测试报告生成。实际用DeepSeek和Qwen两个模型跑了完整评测，发现小模型在格式遵循和复杂指令跟踪方面明显不如大模型。

面试官问"技术难点"：
> 主要有三个：一是LLM-as-Judge的评分稳定性问题，我通过规则校验兜底+降低Judge温度+强制JSON输出来解决；二是多轮对话的上下文管理，需要逐轮调用API并维护完整历史；三是测试用例设计，要平衡覆盖面和区分度，后来增加了边界条件用例才把模型区分开。
