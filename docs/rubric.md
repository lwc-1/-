# 评分维度与评分标准

## 概述

本评测系统采用 5 个维度对大模型在办公文档处理场景下的表现进行评分，每个维度 1-5 分。综合得分为五维度的算术平均值，通过标准为 ≥ 4.0 分。

---

## 维度一：指令完成度 (instruction_following)

评估模型是否完成了用户的全部要求。

| 分数 | 标准 |
|------|------|
| 5 | 完全满足所有指令要求，无任何遗漏 |
| 4 | 基本满足，仅有轻微遗漏（如少写了一个可选字段） |
| 3 | 完成核心要求，但存在明显遗漏（如5条待办只提取了3条） |
| 2 | 只完成少量要求，关键要求缺失 |
| 1 | 基本未完成或答非所问 |

**典型扣分场景：**
- 要求输出 JSON 但只给了纯文本描述
- 要求提取全部待办但遗漏了部分条目
- 多轮任务中忽略了某一轮的追加要求

---

## 维度二：内容准确性 (content_accuracy)

评估回答内容是否与原文事实一致，有无幻觉（hallucination）。

| 分数 | 标准 |
|------|------|
| 5 | 所有信息准确无误，完全基于原文 |
| 4 | 核心信息准确，仅有细枝末节偏差（如日期格式稍有不同） |
| 3 | 大部分准确，但有 1-2 处明显错误 |
| 2 | 多处事实错误或存在明显幻觉（编造不存在的信息） |
| 1 | 大量错误，严重偏离原文事实 |

**典型扣分场景：**
- 金额数字提取错误（如 350,000 写成 35,000）
- 编造原文中不存在的待办事项
- 日期张冠李戴

---

## 维度三：格式正确性 (format_compliance)

评估输出格式是否符合用例要求（JSON、Markdown 表格、邮件等）。

| 分数 | 标准 |
|------|------|
| 5 | 格式完全符合要求，可直接解析/使用 |
| 4 | 格式基本正确，有微小瑕疵（如 JSON 多了一个逗号但结构正确） |
| 3 | 有格式但不完全符合要求（如要求 JSON 数组给了 JSON 对象） |
| 2 | 格式大部分不符合（如要求表格但只给了列表） |
| 1 | 完全不符合格式要求 |

**典型扣分场景：**
- 要求 JSON 但输出不可解析
- 要求 Markdown 表格但缺少分隔行
- 要求邮件格式但缺少主题行和署名

---

## 维度四：完整性 (completeness)

评估是否遗漏关键字段或关键约束条件。

| 分数 | 标准 |
|------|------|
| 5 | 所有关键信息和约束都已覆盖 |
| 4 | 覆盖 95% 以上的关键信息 |
| 3 | 覆盖核心信息但遗漏部分重要内容 |
| 2 | 遗漏多项关键信息 |
| 1 | 信息严重不完整 |

**典型扣分场景：**
- JSON 输出缺少必需字段
- 摘要遗漏了关键决策或时间节点
- 报销记录只提取了 3 条实际有 5 条

---

## 维度五：上下文一致性 (consistency)

评估多轮任务中是否前后矛盾或丢失上下文。对于单轮任务，主要评估回答内部是否自相矛盾。

| 分数 | 标准 |
|------|------|
| 5 | 完全一致，无矛盾，上下文保持良好 |
| 4 | 基本一致，偶有轻微不一致但不影响使用 |
| 3 | 存在可察觉的不一致（如前后数据不同） |
| 2 | 明显矛盾或丢失重要上下文信息 |
| 1 | 严重矛盾或完全忽略之前的对话上下文 |

**典型扣分场景：**
- 第三轮输出丢失了第一轮的内容
- 追加要求后把之前正确的内容改错了
- 压缩摘要时引入了与原文矛盾的表述

---

## 综合评分与通过标准

- **综合分 = 五维度算术平均值**（保留 1 位小数）
- **通过标准：综合分 ≥ 4.0**
- **Bad Case 标准：综合分 < 3.5 或任一维度 ≤ 2**

## 评分方式

本系统支持两种评分方式：

1. **机评（LLM-as-Judge）**：调用 Judge 模型按照上述标准自动评分
2. **人评（人工复核）**：抽取部分用例由人工按相同标准评分

机评与人评的一致率是评估评测系统质量的核心指标。
